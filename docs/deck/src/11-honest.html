Engineering challenges

Seven problems between the models and a working product, and their fixes.

01

ONNX Runtime silently ran on the CPU while claiming the NPU

With the current plugin packaging, providers=["QNNExecutionProvider"] is accepted and ignored. Fix: register the QNN plugin, pick the NPU device through the device API, assert the active provider on every session, and ship npu_check.py so a reviewer can see it.

02

No OpenCV for Windows on ARM64

The camera and every image operation had to work without it. Fix: DirectShow through COM for capture (with CoInitialize on every worker thread), Pillow and numpy for the MediaPipe letterbox, affine crop and landmark mapping.

03

Whisper ships as a precompiled QNN context with no Python runner

Qualcomm's reference decode loop needs torch. Fix: re-implemented the encoder call and the 200-step KV-cache decoder loop in numpy: six layers of self-attention cache, causal mask and forced language prefix.

04

Piper's phonemiser is not built for ARM64

The wheel's espeak bridge fails to import. Fix: phonemise through the espeak-ng CLI and drive the VITS ONNX graph directly; English and Hindi voices at 23× real time.

05

Two GenieX models cannot initialise at the same time

Concurrent loads fail to create HTP contexts. Fix: a single loader thread brings up the language model, then the vision model, while the cursor and speech are already live.

06

A mis-heard fragment launched Windows Search

"Open it." from clipped audio became a search for "it". Fix: pronoun and length guards in the grammar, an allow-list of tools and elements, and no search fallback for short tokens.

07

QNN context caching and chipset generations

A cached compiled graph must be reused, not regenerated, and the development laptop's Hexagon v81 binaries do not run on the OmniBook's v73. Fix: reuse the cache when present, invalidate on mismatch, and ship separate model packs per chipset, both profiled on Qualcomm AI Hub.
